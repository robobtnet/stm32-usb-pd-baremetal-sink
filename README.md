# stm32-usb-pd-baremetal-sink

Minimal bare-metal USB-C Power Delivery sink for STM32 UCPD, with configurable PDO profiles and no RTOS or ST USBPD middleware.

This repository contains a tested STM32CubeIDE example for the NUCLEO-G474RE plus a small reusable PD sink core:

- `Core/Inc/pd_bm.h`
- `Core/Src/pd_bm.c`

The PD core is intentionally kept independent from board-specific details. It does not configure GPIO pins, clocks, NVIC, DMA channels, LEDs, or HAL application logic. The application provides those through `PD_BM_Config`.

## Features

- Bare-metal USB-C PD sink, no FreeRTOS.
- No ST USBPD middleware dependency.
- Uses STM32 UCPD peripheral.
- Configurable fixed PDO profiles.
- Tries optional profiles from highest index to lowest, then falls back to profile 0.
- Profile current is a minimum requirement; if the source advertises more current at the same voltage, the request uses the source current.
- RX uses an application-provided DMA callback.
- TX is handled directly through the UCPD peripheral.

## Profile Selection

`profiles[0]` is mandatory fallback and is always enabled by `PD_BM_Init`.

Example:

```c
pd_config.profiles[0] = (PD_BM_Profile){ 5000U, 500U, 1U };
pd_config.profiles[1] = (PD_BM_Profile){ 9000U, 1000U, 1U };
pd_config.profiles[2] = (PD_BM_Profile){ 12000U, 1000U, 1U };
pd_config.profiles[3] = (PD_BM_Profile){ 15000U, 1000U, 1U };
pd_config.profiles[4] = (PD_BM_Profile){ 20000U, 1000U, 1U };
```

The request order is:

```text
20 V -> 15 V -> 12 V -> 9 V -> 5 V fallback
```

If the profile is `9 V / 1 A` and the charger advertises `9 V / 2 A`, the source PDO matches and the request uses `2 A`.

## Porting To Another STM32 Project

Copy only these two files if you want the reusable core:

```text
Core/Inc/pd_bm.h
Core/Src/pd_bm.c
```

Then configure the board/application layer:

1. Enable UCPD and the CC pins in CubeMX/CubeIDE.
2. Enable the UCPD interrupt and call `PD_BM_IRQHandler()` from the UCPD IRQ handler.
3. Configure UCPD RX DMA as peripheral-to-memory, byte aligned, normal mode, memory increment enabled.
4. Provide callbacks for millisecond tick, RX DMA start, RX DMA stop, and RX DMA byte count.
5. Call `PD_BM_Init(&pd_config)` once.
6. Disable UCPD dead-battery mode after `PD_BM_Init()` hands CC control to UCPD.
7. Call `PD_BM_Task()` continuously from the main loop.

For non-STM32G4 projects, override the LL UCPD include before including `pd_bm.h`:

```c
#define PD_BM_STM32_LL_UCPD_HEADER "stm32xxxx_ll_ucpd.h"
#include "pd_bm.h"
```

## Dead Battery Pins

DBCC/dead-battery support is useful when the target board is powered only from USB-C. It lets the source see a sink pull-down before the MCU firmware starts. Once UCPD is initialized, disable dead-battery mode so the UCPD peripheral owns CC handling.

In this example, that handoff is done after `PD_BM_Init()`:

```c
if (PD_BM_Init(&pd_config) == 0U)
{
  Error_Handler();
}
HAL_PWREx_DisableUCPDDeadBattery();
```
